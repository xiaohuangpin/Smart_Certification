# Smart Certification · 智能制证

### 让 AI 接过会计最日常的那张凭证

面向会计业务的轻量智能记账凭证生成工具：会计维护**会计科目**与**凭证模板**，上传业务 Excel，大模型按模板逐条取数、计算金额并生成凭证草稿；会计核对无误后**采纳**，结果才正式落库。

## 什么是会计凭证（制单）？

会计凭证是经济业务进入账套的“第一道门”。所谓**制单**，就是会计根据发票、合同、银行回单、费用报销单等原始单据，判断业务性质，确定借贷方向，选择会计科目，填写摘要与金额，编制一张借贷平衡的记账凭证，并将原始单据作为附件归档。

它是会计**最基础、最核心、也几乎每天都要重复**的常规工作。凭证是总账、明细账和财务报表的数据源头——科目选得对不对、方向有没有反、金额取得准不准、摘要写得清不清楚，直接决定后续账务和报表的质量。

但制单从来不只是“录入”：

- 要读懂业务，判断该记哪个科目；
- 要从单据或表格里找到正确的金额；
- 要按规则计算税额、分摊、结转；
- 要保证借贷平衡、摘要规范、附件齐全；
- 月底业务量集中时，还要在有限时间里完成大量重复劳动。

经验丰富的会计做得又快又稳，新人却容易在科目、方向和取数上反复踩坑。**这正是 AI 可以接管的部分。**

## 为什么让 AI 来制单？

Smart Certification 把会计的制单经验沉淀为**可复用的凭证模板**，再让 AI 按模板完成取数、计算和分录草稿。会计不再逐张翻表、逐笔找数、逐行核对借贷，而是把精力留给判断、复核和决策。

| 传统手工制单 | 使用 Smart Certification |
| --- | --- |
| 逐张翻单据、逐笔找金额 | 上传业务 Excel，AI 自动定位取数行 |
| 科目与方向依赖个人经验 | 科目、分录、摘要规则沉淀在模板中，团队复用 |
| 金额靠手算或计算器，容易出错 | AI 调用计算器按公式计算，金额保留两位小数 |
| 借贷是否平衡靠事后检查 | 自动汇总借贷合计与差额，不平衡不可采纳 |
| 制单过程难以复核 | 每条分录展示取数行、金额与计算说明，可回看原始表格 |
| 重复劳动多、月底压力大 | 模板配置一次，日常制证快速复用 |

核心优势：

- **模板即规则**：把“老会计怎么做”写成模板，AI 照着执行，新人也能产出稳定结果。
- **自然语言取数**：直接用中文描述金额来源和计算公式，不必编写复杂规则或脚本。
- **结果可追溯**：金额不是黑盒，每条分录都能看到取自哪张表、哪一行、怎么算出来。
- **人工最终拍板**：AI 只出草稿，借贷不平不能采纳，采纳后也不自动入账，责任边界清晰。
- **轻量可私有化**：Flask + Vue + SQLite 单机可跑，数据留在本地，不依赖庞大 ERP 改造。
- **越用越顺手**：业务场景沉淀成模板库，相似业务直接复用，制证从“每次重来”变成“一次配置、长期收益”。

> Smart Certification 不替代会计，而是把重复、规则化的制单动作交给 AI，把专业判断和最终责任留给会计。项目不追求完整财务系统，只聚焦最短链路：**会计科目 → 凭证模板 → 上传 Excel → 智能制证 → 人工确认**。

## 核心能力

| 模块 | 能力 |
| --- | --- |
| 会计科目 | 新增、编辑、搜索、启用 / 停用、删除（未被引用时） |
| 凭证模板 | 新建、编辑、筛选、停用、删除；维护多条借贷分录 |
| 智能制证 | 选择模板 + 上传 Excel，后台调用大模型逐条分录计算金额，生成一张凭证草稿 |
| 结果核对 | 展示分录、摘要、金额、取数行与计算说明，自动校验借贷平衡 |
| 人工确认 | 采纳或废弃凭证；采纳后只读，不直接推送总账 |

## 业务模型

```mermaid
flowchart LR
  A[维护会计科目] --> B[维护凭证模板]
  B --> C[选择启用模板]
  C --> D[上传业务 Excel]
  D --> E[AI 按分录取数与计算]
  E --> F[生成凭证草稿<br/>分录 / 金额 / 来源]
  F --> G{会计核对}
  G -->|采纳| H[凭证状态：已采纳]
  G -->|废弃| I[凭证状态：已废弃]
```

- **会计科目**：科目编码、名称、全称、状态。编码全局唯一，创建后不可修改。
- **凭证模板**：一个业务场景对应一张凭证骨架，由若干分录组成。模板编码自动生成（`TPL-YYYYMMDD-NNN`），每次保存版本号 +1。
- **分录**：方向（借 / 贷）、会计科目、金额来源与计算公式、摘要模板、辅助项。
- **智能制证任务**：一次任务固定产出一张凭证；任务与凭证同表，通过任务 ID 访问。
- **模板快照**：创建任务时固化模板内容，之后修改模板不影响已创建任务。



## 快速开始

### 前置条件

- Python **3.12+**
- [uv](https://docs.astral.sh/uv/)
- Node.js **18+** 与 [pnpm](https://pnpm.io/)
- 一个 OpenAI 兼容的大模型接口地址、API Key 与模型名（智能制证必需）

### 1. 安装后端依赖

在项目根目录执行：

```bash
uv sync
```

### 2. 配置环境变量

在 `backend/` 下创建 `.env`（该文件已被 `.gitignore` 忽略，切勿提交真实密钥）：

```ini
# 数据库；相对路径基于项目根目录
SC_DATABASE_URL=sqlite:///data/app.db
SC_DEBUG=false

# 大模型（OpenAI 兼容接口）
SC_LLM_BASE_URL=https://api-inference.modelscope.cn/v1
SC_LLM_API_KEY=your-api-key
SC_LLM_MODEL=deepseek-ai/DeepSeek-V4.1-Flash-1017
```

> 未配置 `SC_LLM_*` 时服务仍可启动，科目与模板功能可用；发起智能制证会返回 `ENGINE_NOT_CONFIGURED`。

### 3. 安装并构建前端

```bash
cd frontend
pnpm install
pnpm build
```

构建结果直接写入 `backend/app/dist`，由后端托管。

### 4. 启动服务

```bash
cd backend
uv run flask --app app run --host 127.0.0.1 --port 5000
```

浏览器访问 **http://127.0.0.1:5000**。

启动时会自动建表并写入种子数据（2 个场景、6 个示例科目），可重复执行，不会重复写入。

### 5. 开发模式（可选）

前后端分离调试时，开两个终端：

```bash
# 终端 A：后端
cd backend
uv run flask --app app run --debug --port 5000
```

```bash
# 终端 B：前端（Vite 已配置 /api 代理到 127.0.0.1:5000）
cd frontend
pnpm dev
```

访问 **http://127.0.0.1:5173**，修改前端代码可热更新。

## 配置说明

所有变量使用 `SC_` 前缀，读取自 `backend/.env` 或进程环境变量。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SC_DATABASE_URL` | `sqlite:///data/app.db` | 数据库连接；SQLite 相对路径基于项目根目录 |
| `SC_DEBUG` | `false` | Flask 调试模式 |
| `SC_UPLOAD_DIR` | `<项目根>/data/uploads` | 上传 Excel 落盘目录 |
| `SC_SOURCE_RETENTION_DAYS` | `30` | 源文件保留天数，供清理命令使用 |
| `SC_LLM_BASE_URL` | 空 | 大模型 OpenAI 兼容接口地址 |
| `SC_LLM_API_KEY` | 空 | 大模型 API Key |
| `SC_LLM_MODEL` | 空 | 模型名称 |

生产环境建议直接注入环境变量，不要把 `.env` 打包进镜像或提交到仓库。

## 使用方式

### 第一步：维护会计科目

进入顶部导航 **会计科目**：

1. 点击「新增科目」，填写科目编码（4–20 位字母、数字、`_`、`-`）、名称、全称。
2. 科目编码全局唯一，保存后不可修改，避免历史模板引用失效。
3. 不使用某科目时选择「停用」；停用后不会出现在模板编辑页的科目下拉中，但已保存的模板仍保留原科目快照。
4. 已被模板引用的科目只能停用，不能删除。

### 第二步：维护凭证模板

进入 **凭证模板 → 新建模板**：

1. **基本信息**：模板名称（2–50 字）、业务场景、标签（可选，最多 10 个）、状态、备注。
2. **分录**：至少一条，逐行填写：
   - **方向**：借 / 贷
   - **会计科目**：远程搜索启用科目，保存编码与名称快照
   - **金额来源与计算公式**：用自然语言描述取数口径和算式，这是 AI 制证的核心指令。例如：
     - `取“税金计提明细表”中代扣房产税额，合计后填入`
     - `取“收入明细”中金额合计，按 6% 计算税额，保留两位小数`
   - **摘要模板**：凭证摘要，可含占位符，例如 `计提{{月份}}房产税`
   - **辅助项**：可选，自由配置键值，不依赖统一字典
3. 保存时整体提交并校验；保存后版本号递增，自动生成模板编码。
4. 模板停用后不能被智能制证选用；有制证记录的模板只能停用，不能物理删除。

![凭证模板列表](docs/凭证管理.PNG)

### 第三步：发起智能制证

进入 **智能制证**：

1. 选择一张**启用状态**的模板。
2. 上传业务 Excel（`.xlsx` / `.xlsm`，单文件不超过 20MB）。
3. 点击「提交智能制证」。后端创建任务并在后台执行：
   - 解析 Excel 所有可见工作表，按行号转为 Markdown
   - 对模板中的每条分录，分别让 AI 定位取数行、执行算式、返回金额与计算说明
   - 汇总借贷合计、差额并落库
4. 页面每 1.5 秒轮询任务状态，完成后自动展示结果。

### 第四步：核对并采纳

结果页会展示凭证头部、分录明细、借贷合计与差额。展开分录行或点击「取数来源」，可查看取数行与计算说明，并可打开原始表格定位。

![AI 预生成凭证结果](docs/AI预生成凭证结果展示.PNG)

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 采纳凭证 | 任务已完成、状态为待确认、借贷差额为 0、无校验错误 | 凭证状态变为**已采纳**，内容只读 |
| 废弃凭证 | 状态为待确认 | 凭证状态变为**已废弃** |
| 重新发起 | 结果不平衡或失败 | 回到智能制证页重新提交 |

- 借贷不平衡时结果仍会展示，但**不能采纳**，需调整模板的金额来源或 Excel 后重新生成。
- 采纳后不推送总账 / ERP，仅在本系统落库保存。

## Excel 准备建议

为保证取数准确，上传前建议确认：

1. **只使用可见工作表**：隐藏 sheet 会被跳过。
2. **公式需有计算结果**：解析使用 `data_only=True`，只读取 Excel 中已缓存的值。若金额单元格是公式且从未在 Excel 中计算过，可能读到空值——请先用 Excel 打开并保存一次。
3. **保留表头与行结构**：模型依赖行号和列名定位取数，避免把关键说明放在图片、批注或隐藏列中。
4. **合并单元格可用**：解析时会自动拆分并把值填充到区域内每个单元格。
5. **金额单位统一**：模板中写清单位（元 / 万元），避免 AI 按错误量级计算。
6. **控制文件大小**：建议只保留与本次制证相关的工作表，避免超过 20MB 或无关内容干扰取数。

## 数据与备份

| 路径 | 内容 |
| --- | --- |
| `data/app.db` | SQLite 数据库（含 `-wal`、`-shm` 伴随文件） |
| `data/uploads/YYYY/MM/` | 上传的原始 Excel，文件名与任务 ID 对应 |
| `backend/app/dist/` | 前端构建产物，可由 `pnpm build` 重新生成 |

备份步骤：停止服务 → 复制整个 `data/` 目录。数据库使用 WAL 模式，运行中直接复制可能不一致，建议先停服或使用 SQLite 备份命令。

## 接口概览

统一前缀 `/api/v1`，成功响应 `{"data": ..., "meta": ...}`，失败响应 `{"error": {"code", "message", "details"}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| GET/POST | `/accounts` | 科目列表 / 新增 |
| GET/PUT/DELETE | `/accounts/{id}` | 科目详情 / 编辑 / 删除 |
| POST | `/accounts/{id}/enable`、`/disable` | 启用 / 停用科目 |
| GET/POST | `/templates` | 模板列表 / 新建 |
| GET/PUT/DELETE | `/templates/{id}` | 模板详情 / 保存 / 删除 |
| POST | `/templates/{id}/disable` | 停用模板 |
| GET | `/options` | 场景与启用科目选项 |
| POST | `/smart-generation` | 创建制证任务（`multipart/form-data`：`template_id`、`file`、可选 `context` JSON） |
| GET | `/smart-generation/{taskId}` | 查询任务与凭证结果 |
| GET | `/smart-generation/{taskId}/source` | 下载原始 Excel |
| POST | `/smart-generation/{taskId}/adopt` | 采纳凭证 |
| POST | `/smart-generation/{taskId}/discard` | 废弃凭证 |

制证任务状态：`pending` → `running` → `succeeded` / `failed`。
凭证状态：`pending`（待确认）→ `adopted` / `discarded`。

## 常见问题

**Q：提交制证后提示「智能制证引擎未接入」？**
未配置 `SC_LLM_BASE_URL`、`SC_LLM_API_KEY`、`SC_LLM_MODEL`，或配置不完整。补齐后重启后端。

**Q：提示「Excel 读取失败」？**
确认文件为 `.xlsx` / `.xlsm`、未加密、扩展名与实际格式一致；`.xls` 需另存为 `.xlsx`。

**Q：金额取到了空值或 0？**
金额单元格可能是公式且没有缓存值。用 Excel 打开文件、全量重算并保存后再上传。

**Q：为什么不能采纳？**
采纳要求：任务成功、凭证为待确认、借贷差额为 `0.00`、无校验错误。请检查模板金额来源是否覆盖了所有分录、Excel 数据是否齐全。

**Q：模板 / 科目删除不了？**
已被制证任务引用的模板、已被模板引用的科目，只允许停用。

**Q：前端页面显示 503 `FRONTEND_NOT_BUILT`？**
尚未构建前端。在 `frontend/` 执行 `pnpm build` 后重启后端。

**Q：页面能打开但接口报错？**
开发模式下确认 Vite（5173）与后端（5000）都已启动；生产模式下确认前端构建产物位于 `backend/app/dist`。

## 范围与限制

- 单用户、本地 / 内网使用，无登录、无权限、无多租户。
- 一次制证任务固定产出一张凭证，不支持批量制证与定时制证。
- AI 结果必须人工核对并采纳，系统不会自动入账。
- 不推送总账 / ERP，不提供凭证打印与报表。
- 凭证生成后不支持在线编辑；不满意可重新生成或废弃。
- 上传文件仅支持 `.xlsx` / `.xlsm`，前端限制 20MB。
- 智能制证按分录逐条串行调用模型，分录越多耗时越长；后台单 worker 串行执行。
